## Part 1 — compose-multiplatform-chess: publish both artifacts

### 1a. `coachApi` — add `js(IR)` + `maven-publish`
File: `coachApi/build.gradle.kts`
- Add `js(IR) { nodejs() }` target (mirrors chess-core's js target; coachApi is serialization-only, no browser needed for tests). No `binaries.library()` needed on the source side — only the RN consumer needs that.
- Add `` `maven-publish` `` plugin.
- Add the maven-publish block (mirror chess-core/build.gradle.kts lines 80-125):
  - Version: `val coachApiVersion = (env COACH_API_VERSION ?: property "coachApiVersion" ?: "0.1.0").removePrefix("coachApi-v")`

  - `publications.withType<MavenPublication> { pom { name="coachApi", description=..., GPL-3.0, scm } }`

### 1b. `onDeviceAi` — add `js(IR)` + `maven-publish` + JS actuals
File: `onDeviceAi/build.gradle.kts`
- Add `js(IR) { nodejs() }` target.
- Add `` `maven-publish` `` plugin.
- Add the maven-publish block (mirror as above, `onDeviceAiVersion`, `ON_DEVICE_AI_VERSION`).
- Normalize the hardcoded coroutines version string (`"org.jetbrains.kotlinx:kotlinx-coroutines-core:1.9.0"`) → `libs.kotlinx.coroutines.core` (the version catalog already has it). Minor cleanup to match the convention chess-core uses.

New files: `onDeviceAi/src/jsMain/kotlin/com/example/ondeviceai/` (3 no-op actuals, mirroring the existing wasmJsMain stubs):
- `OnDeviceTextGeneratorFactory.js.kt` → `UnsupportedTextGenerator` (copy of wasmJsMain/...Factory.wasm.kt)

The `iosMain` intermediate source set is created manually in the build file; `jsMain` comes from the KMP hierarchy automatically (no manual `dependsOn` needed for js).

### 1c. Publish workflow
New file: `.github/workflows/publish-on-device-ai.yml`
- Mirror `publish-chess-core.yml` structure.
- **Two publish steps in one job**: publish coachApi first, then onDeviceAi (order matters — onDeviceAi's metadata references coachApi).
- Trigger: `push: tags: ['on-device-ai-v*']` + `workflow_dispatch` with version input.
- Version env: `ON_DEVICE_AI_VERSION` (drives onDeviceAi) + `COACH_API_VERSION` (drives coachApi — for simplicity, both use the same version number on a joint tag; the artifacts just have different names).
- Commands: `./gradlew :coachApi:publishAllPublicationsToGitHubPackagesRepository :onDeviceAi:publishAllPublicationsToGitHubPackagesRepository`

### 1d. README — public API & boundary documentation
File: `README.md`
- Add a new section `## `:onDeviceAi` & `:coachApi` — public API & dependency boundary` mirroring the existing `:chess-core` section (the one PR #79 added). Document:

  - Public API surface: `MoveCoachOrchestrator`, `RulesQaOrchestrator`, `OpeningExplainer`, `AiRoutePolicies`, `RuleLookupTool`, the model/result sealed types.
  - Published coordinates: `io.github.ber4444:onDeviceAi:<version>` + `io.github.ber4444:coachApi:<version>`.
  - Tag-driven publish: `on-device-ai-v*`.
- Update the Modules list to note onDeviceAi + coachApi are now published.
- Add Gradle task entries: `:coachApi:publishToMavenLocal`, `:onDeviceAi:publishToMavenLocal`.

### 1e. CLAUDE.md / AGENTS.md
- Add onDeviceAi + coachApi to the module boundary section, noting they're published to GitHub Packages (like chess-core) and the `api(project(":coachApi"))` seam.

## Part 2 — reactnative: smoke-consumer module

### 2a. New module: `on-device-ai/`
Mirror the structure of the existing `chess-core/` consumer module, but minimal (no `@JsExport` facade, no `copyJsToApp`):

File: `on-device-ai/build.gradle.kts`
- `js(IR) { nodejs() }` only (the target that proves the artifacts resolve + compile).
- Dependencies:
  ```kotlin
  implementation("io.github.ber4444:onDeviceAi:${property("onDeviceAiVersion")}")
  // coachApi comes transitively via onDeviceAi's api() dep, but declare it explicitly
  // so the smoke test can reference coachApi types directly:
  implementation("io.github.ber4444:coachApi:${property("coachApiVersion")}")
  implementation(libs.kotlinx.coroutines.core)
  ```
- A single `commonMain` file `SmokeTest.kt` that references a public type from each artifact (e.g. `AiRoutePolicies.moveCoachOffline` from onDeviceAi, `OpeningExplainResponse` from coachApi) to prove they resolve.
- A `commonTest` that asserts the smoke references don't throw at class-load time.

File: `on-device-ai/settings.gradle.kts`
- Mirror `chess-core/settings.gradle.kts` — same `GitHubPackages` maven repo + credential chain.

File: `on-device-ai/gradle.properties`
- `onDeviceAiVersion=0.1.0` + `coachApiVersion=0.1.0`.

File: `on-device-ai/gradle/libs.versions.toml`
- Mirror chess-core's (Kotlin, coroutines versions only).

### 2b. README (RN repo)
- Add a note that `on-device-ai/` is a smoke consumer proving the published artifacts resolve, with a pointer that a full `@JsExport` facade + app integration is a follow-up.

### 2c. CI (RN repo)
- Add an `on-device-ai` job to `.github/workflows/ci.yml` mirroring the `chess-core` job: `./gradlew jsNodeTest` with `GITHUB_ACTOR` + `GITHUB_PACKAGES_TOKEN` env. Proves the artifacts resolve from GitHub Packages in CI, not just locally.

```bash
cd on-device-ai && ./gradlew jsNodeTest   # resolves both artifacts + compiles + test passes
```
